## 提示词 A — 首次启动 D3（主提示词）

```text
你正在继续开发我的 macOS 桌面应用 FrameWeave · 映构。

本轮请实际执行 D3，不是再输出一份开发建议，也不是重新设计界面。

1. 当前工程及目标子目录适用的 AGENTS.md。

新文档通常位于 docs/desktop-workbench/frameweave-d3/，两份原始交接位于该目录的 sources/；也可能作为本对话附件提供。请按文件实际位置读取，不编造路径。

如果发现已有 D3_WORKLOG.md、D3_HANDOFF.md 或部分 D3 代码，先读取并从实际未完成点继续，不覆盖重做。

二、已经确定的基线

- 项目根目录：/Users/shaoqitang/Documents/ChatGPT/FrameWeave。
- 品牌：FrameWeave / 映构。
- identifier：com.sharkytang.frameweave.workbench。
- npm package：frameweave-desktop-workbench。
- Rust executable / library：frameweave-workbench / frameweave_workbench_lib。
- 已有 Tauri 2 + React / TypeScript / Vite、八页界面、共享组件、hash 路由和独立生产 .app。
- 已有原生/演示/未连接适配器。默认个人空间与内存演示 Repository 隔离。
- 业务目前按 D2 交接尚无 SQLite、无个人视频导入；shell.json 只保存窗口与路由。
- 更名与 shell.json 目录迁移已经完成，不得再迁移一次，不得换 identifier。
- 已修复 Cmd+Q 绕过退出保护的问题，必须继承；Cmd+W、窗口恢复和深层页恢复也要保留。
- 既有 D2 和更名成果有未提交改动。旧文档中“初始无用户改动”不是当前可以清空工作区的依据。

三、本轮唯一目标

完成 D3：Rust SQLite、原生素材导入、管理副本、真实媒体播放、个人空间重启恢复。

用户闭环：
独立启动 FrameWeave.app → 原生选择本地视频 → 复制入个人资料库 → 搜索/编辑资料/收藏/归档恢复 → 在现有视频拆解页真实播放和 seek → 退出重开仍找到同一素材及已保存资料。

本轮不要实现：
- 下载/文案插件、ASR、字幕纠错、Python 服务、端口探测。
- AI/模型/联网分析/榜单/自动转码。
- D4 字幕或个人时间笔记持久化。
- D5 创作项目、脚本、分镜、方法库或成片持久化。
- 全新主题/品牌/页面架构、永久删除、全库清空、目录扫描、云同步、产品备份恢复。

四、执行顺序

按照详细规划逐批执行：
D3.0 继承基线与最小接口映射；
D3.1 SQLite 与个人素材 Repository；
D3.2 原生导入、管理副本与中断恢复；
D3.3 个人素材库、首页与真实保存状态；
D3.4 原生媒体播放、深层页和退出协调；
D3.5 测试、最终打包与交接。

本轮授权完整 D3。每批达到规划中的闸门后继续，无阻塞不必反复问我是否进入下一小批；但不要跳过验证，不要进入 D4。

只做继承性检查，不从 D0 重做。先检查当前源码再确定具体文件和依赖；复用已存在的类型、Repository 和 adapter，不能为了照搬规划名称新建第二套系统。

五、不可违反的实现约束

1. 真正 macOS 桌面应用，最终 .app 不依赖开发服务器。保留现有八页和 D2 视觉/交互，不改成网页交付。
2. SQLite 和文件访问在 Rust，前端经既有原生 adapter 调用类型化业务命令；页面不得直接 SQL、invoke 或拼本地路径。
3. AppData 通过运行时解析。保留 shell.json，新业务库独立；不把媒体/数据写进 .app、仓库、public 或浏览器缓存。
4. 导入必须来自原生文件选择。前端不能提交任意路径获得读盘能力。采用受控选择 token 或 Rust 持有选择结果。
5. 只复制、不移动或删除用户原视频。分块复制/摘要、顺序队列、真实字节进度、每项结果、可取消；不整文件 base64。
6. 副本发布和 SQL 写入有中断核对。只有数据库确认才显示导入成功；重复内容不新增正式副本，同名不同内容不覆盖。
7. 已归档重复不自动恢复。管理副本缺失后，同内容重新导入可修复同一 asset id，不覆盖原资料。
8. 媒体读取只放行应用的正式管理副本；不得开放整个 home 或整个 AppData，不关 CSP，不开通用 fs/shell/SQL 命令。
9. Rust 仍要校验 token、asset id、路径归属、字段和修订；不能认为 capabilities 会替代业务校验。
10. 演示与个人数据严格隔离；重置演示不写/删个人 SQLite。个人视频不得套用演示字幕、笔记或 AI 分析。
11. “已入库”和“可播放”分开。D2 只验证过无声 H.264 示例，D3 必须核验实际原生画面、seek 和含音轨素材；未测编码不能说支持。
12. 保留受控 Cmd+Q，并处理导入中的安全取消/提交收尾；Cmd+W/重激活/重复启动不得重复建库或重复写队列。
13. 保存失败保留用户输入，未确认落库不显示“已保存”；素材资料编辑不能越界变成 D5 脚本自动保存。
14. 测试使用隔离资料根，故障注入不得碰我的正式 AppData；默认诊断不输出完整源路径或私人媒体内容。
15. 继续让 AI/下载/雷达返回 NOT_CONNECTED；真实本地导入标识不能伪装成这些服务的 jobId。

六、工作区保护

- 保留全部已有 staged/unstaged/untracked 内容、AGENTS.md、origin 和 D2 产物。
- 不 reset/clean、不自动 stash、不强制覆盖、不自动 commit/push、不改远端。
- 更名临时备份是否还在需核实；不能假装已备份，不重复迁移旧品牌数据。
- 本轮产物写入 deliverables/D3，不覆盖 deliverables/D2。
- 数据库已有数据时先按安全方式保留一致副本，不复制活跃主库单文件冒充完整备份，不自动删库重建。

七、验证与交付

复用当前工程实际存在的 typecheck、ui:build、test、native:test、test:ui、desktop:build 和格式检查，确认正确 package/工作目录后运行。

按照详细规划中的 54 项 D3 验收记录 PASS / FAIL / NOT_RUN / MANUAL_PENDING / NOT_APPLICABLE。历史测试数量不作为本次通过证据；浏览器通过不能冒充最终原生 .app 通过。

交付：
- 真实 D3 源码与测试。
- deliverables/D3/FrameWeave.app。
- FrameWeave-D3-mac-arm64.zip 及对应 BUILD_MANIFEST.json。
- D3_WORKLOG.md、D3_DATA_CONTRACT.md、D3_NATIVE_VALIDATION.md、D3_TEST_RESULTS.json、D3_HANDOFF.md，名称可沿用工程既有约定但须给实际位置。
- 实际媒体支持矩阵、截图索引、数据路径、已知限制和人工未测项。

最后一次代码修改后必须重新构建；清单中的架构/大小/签名状态/哈希对应最终产物。没有 Developer ID 或公证就如实写明。

原生捕获视频区域灰色时保留原始截图和验证说明，不能拼接浏览器截图伪装通过。人工 Finder/Dock/声音/中文输入法/断网等没做就写未测。

如果无法在本次完成全部 D3，请停在数据安全的可恢复边界，更新 D3_WORKLOG 和交接，写明完成任务编号、失败证据和下一项准确动作，不空泛承诺稍后完成。

现在先读取文档和当前工程，简要确认复用点与保护区，然后直接实施 D3。完成后停止，不开始 D4。
```

## 使用时不要遗漏的四点

1. 必须在已有 `FrameWeave` 工程继续，不新建“第二个映构”。
2. 新文档是待执行要求，原交接是基线事实；Codex 要核对当前源码后再勾选任务。
3. D3 的“保存”只针对本轮素材资料，不把 D2 演示脚本/方法/时间笔记一并持久化。
4. 本轮完成标准是可独立启动的真实桌面闭环，不是截图、浏览器原型或看起来已经接入的 AI。
