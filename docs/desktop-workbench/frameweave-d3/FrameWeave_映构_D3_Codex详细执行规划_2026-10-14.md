## 2. D3 的产品目标与停止边界

### 2.1 本轮唯一用户闭环

```text
独立启动 FrameWeave.app
  → 进入默认个人空间
  → 用 macOS 原生选择器选择本地视频
  → 明示“复制到映构资料库，不移动原文件”
  → 原生后台复制并保存素材记录
  → 在素材库搜索、修改资料、收藏、归档与恢复
  → 打开同一素材，在现有拆解页面真实播放、暂停、拖动和调速
  → 正常退出并重新启动
  → 素材及已保存资料仍在，深层页能重新找到正确视频
```

这里的“拆解页面”本轮只是**真实播放器及素材上下文**。没有真实分析报告，没有个人字幕或时间笔记保存，没有脚本/分镜持久化。

### 2.2 本轮必须做

| 能力 | 最低交付 |
|---|---|
| Rust SQLite | 数据库初始化、版本化迁移、个人 Repository、参数校验、失败状态 |
| 原生导入 | 明确用户选取、单个/多个文件、按文件显示真实结果、可取消复制 |
| 管理副本 | AppData 内受控副本，不依赖 Downloads 等原位置长期存在 |
| 素材持久化 | 沿用已有素材字段，保存标题、标签、收藏、归档和现有资料字段 |
| 真实播放 | 受限本地媒体来源、播放/暂停/seek/倍速、音频验证与真实错误提示 |
| 重启恢复 | 原个人素材、保存结果、现有窗口与深层页恢复；默认暂停，不自动播放 |
| 安全与可恢复性 | 不任意读盘、无演示污染、复制中断不产生假成功、缺失素材不崩溃 |
| 桌面交付 | 新 D3 `.app`、ZIP、构建清单、测试证据与交接，保留 D2 产物 |

### 2.3 本轮明确不做

- 下载插件、视频解析、分享链接抓取、文案下载、ASR、字幕纠错、Python 服务连接或端口探测。
- 真实 AI、多模态模型、模型下载、联网分析、远程密钥配置、趋势榜单采集。
- D4 的 SRT/TXT 导入、字幕对齐、时间点笔记持久化；D5 的脚本/分镜/方法库/成片版本持久化。
- 新的 UI 主题、品牌或信息架构；不借 D3 重做八页，不用新的设计稿替换 D2。
- 原文件引用模式、目录监控、递归扫描、外置素材库切换、网络盘、云同步、账号系统。
- 自动转码、FFmpeg 产品集成、关键帧提取、封面分析、完整媒体探测服务。
- 永久删除媒体、清空个人资料库、产品级备份恢复界面、自动更新、分发公证或跨平台打包。
- 通用任务调度系统、WebSocket/HTTP 服务、为后续所有功能预建几十张表。

**范围例外只允许修复阻断 D3 或导致原有 D2 回归的问题，并在交接中解释。** 拖拽导入、播放位置记忆、封面缓存等不作为完成门槛，不得挤占核心任务。

## 3. 最小架构：沿用已有边界

```text
现有页面 / 共享组件 / 路由
          ↓
现有领域服务与 Repository / Port
          ↓
┌──────────────────────┬─────────────────────────┐
│ 演示：原独立内存实现    │ 个人：新增 Rust 原生实现    │
│ fixtures，退出即重置    │ 类型化 IPC，真实保存结果    │
└──────────────────────┴────────────┬────────────┘
                                    ↓
                 Rust 应用服务：校验、导入、素材管理
                      ↓                         ↓
             SQLite / 版本化迁移        受控文件库 / 媒体地址
```

### 3.1 实施规则

1. 先列出现有类型、Repository、adapter 和页面数据流，输出“既有实现 → D3 替换/扩展点”映射。
2. 只替换个人素材相关的未实现适配器；演示与 `NOT_CONNECTED` 实现继续保留。
3. 原生数据库和文件访问只在 Rust 层。不得在页面中引入 SQL 插件、`fetch(localhost)`、直接 `invoke`、Node 文件 API 或本地绝对路径拼接。
4. Tauri 调用集中在已有原生 adapter。原生方法返回窄 DTO 和明确错误，不开放通用 SQL、任意文件读取或任意路径删除。
5. 没有既有 SQLite binding 时，可采用与当前工程兼容的 Rust SQLite binding；优先简单、稳定的直接访问方案。核对当前 lockfile 与官方文档，不在本规划中虚构精确依赖版本。
6. 复制、计算摘要、数据库初始化等不阻塞 UI 线程；采用单个受控导入 worker，不为本阶段引入跨进程服务。
7. 用同一写入协调机制处理数据库写入。导入时不长时间持有 SQL 写事务，页面仍能读素材和显示进度。
8. 第一条真实导入成功后，立即做一次生产原生媒体加载验证；不要等所有页面接线完才发现协议/CSP/编码问题。

### 3.2 数据目录建议布局

下面是 **D3 新增布局建议**。若当前工程已定义同等目录约定，则复用并记录差异。

```text
<AppData for com.sharkytang.frameweave.workbench>/
├── shell.json                        # 既有，仅窗口/路由，保留原格式
├── data/
│   └── frameweave.sqlite3            # D3 个人元数据；媒体字节不进 SQL
├── media/
│   └── originals/
│       └── <generated-asset-id>.mp4  # 应用生成文件名；MOV 等保留合理后缀
├── staging/
│   └── <import-attempt-id>.part      # 不向 WebView 暴露
└── recovery/
    └── <attempt-id>/                # 必要时隔离可疑残留，不当作素材展示
```

- 使用框架的应用资料目录解析能力；不硬编码用户 home。数据库只存受控相对路径。
- 不把数据写入 `.app`、源码目录、`public`、临时目录或浏览器 `localStorage`。
- `media/originals` 是媒体加载唯一必要新增文件范围；数据库、暂存、诊断、`shell.json` 不开放给 WebView。
- 用户选取的原始文件只读，源目录不自动加入永久访问列表。D3 不需要重启后继续访问原文件。
- D3 测试使用独立测试资料根；不得对用户真实 AppData 做重置、故障注入或批量删除。

## 4. 数据库和领域模型实施规格

### 4.1 建库与迁移

- 首次启动只新建 D3 业务数据库；D2 没有业务数据库，因此**没有旧素材库迁移，也不从 fixtures 导入个人记录**。
- 保留 `shell.json`，不把窗口/路由迁移到 SQLite。本轮只增加业务库。
- 采用递增 schema version 与迁移记录；启动时完成必要迁移后才向页面报告可写。
- 迁移可重复启动、可事务回滚；失败不删库重建，不伪装成“空素材库”。
- 遇到比当前程序更新的 schema，进入“不支持的数据版本”阻断状态，不尝试降级或覆盖。
- SQL 参数化，外键约束每个连接显式开启并测试；不要依赖默认值。[T6]
- D3 默认先采用单写入协调和短事务，明确记录实际 journal / synchronous / busy timeout 设置。没有实测需求不为“性能”关闭持久化保障。
- WAL 不作为硬性要求。采用 WAL 时，必须相应处理 checkpoint、异常关闭和备份文件集；不能复制一个活跃主库文件就声称完整备份。[T4][T5]

### 4.2 最小实体：语义契约，不要求逐字照搬表名

| 实体建议名 | 最小职责与字段 |
|---|---|
| `assets` | 稳定 id、标题、原文件显示名、`source_kind=manual_import`、管理副本相对路径、SHA-256、实际字节数、导入/修改时间、收藏、归档时间、修订号 |
| `tags` | 标签 id、显示名、规范化检索值；空白/重复处理明确 |
| `asset_tags` | 素材与标签关联，联合唯一，外键一致 |
| `import_attempts` | 本地导入尝试 id、batch id、候选 asset id、状态、暂存/目标相对路径、必要校验信息、终态、脱敏错误和时间 |
| `schema_migrations` | 已应用迁移版本与必要的识别信息；也可复用项目既定机制 |

**不得在 D3 新增并接通** transcripts、个人 notes、analysis reports、creative projects、method notes、trends 等后续业务表。

### 4.3 `assets` 字段约束

- `id`：原生生成的稳定不透明 ID；与路由中的真实 asset id 一致，不能重启后重生成。
- `title`：非空、去首尾空格；复用既有长度限制，无限制时默认最多 200 个字符；保存校验在 Rust 再做一次。
- `original_filename`：仅显示来源信息，按不可信纯文本渲染，不用于目标文件路径。
- `managed_relpath`：只能解析到受控 `media/originals`；拒绝绝对路径、`..`、异常编码路径和符号链接逃逸。
- `sha256`：对导入副本实际字节计算，参与个人空间内容去重；它不是版权证明、病毒扫描或相似视频识别。
- `byte_size`：真实复制字节数，大于零；大文件不能使用会溢出的窄类型。
- `duration_ms / width / height`：允许为空；通过实际媒体加载结果取得时再保存。不能用示例值填充，也不能由 `.mp4` 推断编码和时长。
- 编码/容器字段：只有有依据时记录；仅从扩展名得到的提示必须明确是 `hint`，未知保持未知。
- `favorite / archived_at`：沿用 D2 收藏和归档语义；归档不删除副本，恢复不重新复制。
- `revision`：沿用现有修订模型；更新后递增，冲突不能用旧请求静默覆盖新状态。
- 简介、学习目标等其他资料字段：只持久化现有素材详情已定义的字段。不要借“资料编辑”新增时间笔记或个人脚本。
- 时间：数据库和 IPC 采用一致的 UTC 表示，UI 按用户本地时区展示；测试不依赖写死的当前日期。

### 4.4 去重、排序、搜索

- 同一文件换名字再次导入：默认复用同一 asset，显示“已在素材库中”，不增加第二份正式副本。
- 同名但字节不同：允许作为不同素材，不覆盖原记录或原副本。
- 已归档的重复素材：提示“已在归档中”，用户可主动恢复；不隐式取消归档、修改标签或覆盖标题。
- 第一版使用现有标题/标签检索与筛选语义，不接向量库，不自动分词扩展研究范围。
- 收藏、归档筛选和排序在重启后反映实际数据库数据；空结果与加载失败必须区分。
- 列表分页/增量加载复用现有约定；不一次把视频字节或所有原生地址加载进页面。

## 5. 原生导入：文件选择、复制和真实结果

### 5.1 入口与用户授权

- 素材库主要按钮为“导入本地视频”；工作台快捷入口复用同一流程。
- 使用 macOS 原生选择器，支持文件多选，不扫描目录。取消选择是正常结果，不产生失败任务。
- 选择前/确认时说明：“视频将复制到映构资料库，占用额外空间；原文件不会移动或删除。”
- 源文件必须来自这次原生选取。推荐由 Rust 打开选择器并持有源文件句柄/内部选择记录；前端只获得不透明 selection token 或 batch id。
- 若使用前端 dialog adapter，仍要在 Rust 校验与该次原生选择关联的允许项。**不得把 `import(path: string)` 变成可读取任意本机路径的后门。**
- D3 只承诺手动原生文件选择，不承诺拖拽、外部插件、系统“打开方式”或自动监听目录。

### 5.2 首版媒体范围

- 默认候选导入范围为 MP4 / MOV 容器；最终范围由本机验证矩阵决定，并在选择器说明与错误文案中一致呈现。
- 基线正向测试：实际自制 MP4 / H.264；另外新增含音轨的可控测试素材进行原生音频验证。
- 扩展名只是初筛，结合受限文件头检查与实际媒体加载判断。零字节、目录、设备、明显伪装文件应拒绝；看似媒体但不可解码的文件不宣称播放成功。
- “已入库”表示副本和元数据可靠保存，不等于“所有画面/声音均可解码”。存储状态和播放状态分开。
- MOV、HEVC 或其他编码未测时明确“未验证”；不因机器是 Mac 就宣称支持。
- 不引入自动转码补救。失败时保留可理解的原因与后续说明，不偷偷连接 Python 或下载解码器。

### 5.3 限额与资源控制

- 默认一次最多选择 20 个候选文件，单文件上限建议 5 GiB；这是本轮可调整的产品保护阈值，不是平台限制。集中配置，UI 和后端一致。
- 默认同时复制 1 个文件，其余等待；不一口气打开整批视频播放或解码。
- 大文件分块读写并计算摘要，禁止整文件读入 JS、base64 或一次性塞进 Rust 内存。
- 预检查可用磁盘空间并留出数据库/操作余量，但不把预检查当作最终保证；复制和提交过程仍处理磁盘写满。
- 进度根据已复制字节/真实总字节展示。校验、提交等阶段可用不定进度，不用计时器伪造百分比或预计时长。
- 实际大文件测试体量要记录。没有测到上限，就只声明实现了上限校验，不声称通过 5 GiB 压力测试。

### 5.4 单文件状态机

```text
selected → queued → copying → validating → staged → committing → imported
                       │           │          │           │
                       ├───────────┴──────────┴───────────┴→ failed
                       └→ cancelled

validating / staged → duplicate(existingAssetId)
进程中断 → 启动核对 → interrupted / recovered-imported / needs-review
```

实现允许合并内部状态，但对外至少区分：等待、复制、校验/入库、成功、重复、失败、取消、中断。`batchId`/`attemptId` 是真实本地导入标识，不是下载/AI jobId；不得混用 `NOT_CONNECTED` 服务任务。

### 5.5 提交顺序与一致性

1. 验证原生选择来源、普通文件属性、读权限、候选类型与限额；创建真实导入尝试。
2. 打开源文件并记录必要身份/大小信息，只读复制到同一 AppData 下的 `.part`；复制期间逐块计算摘要。
3. 关闭/刷新输出，核对实际大小；检查源文件复制前后是否明显变化。有变化则报错，不把不确定结果标作成功。
4. 将摘要、字节数、受控目标名等恢复所需信息写入导入记录；先检查数据库去重。
5. 重复时删除本次应用创建的暂存文件，返回既有 asset；不改既有元数据和归档状态。
6. 非重复时记录 `committing`，将 `.part` 发布到应用生成的正式目标路径，采用不覆盖既有文件的方式。
7. 用一个短 SQL 事务写入素材记录和导入终态。只有事务确认后，UI 才提示“已导入”。
8. 复制、文件发布和 SQL 提交不是跨文件系统/数据库的单一原子事务；必须按第 6 节核对中断窗口，不用“用了 transaction”代替恢复设计。

不得覆盖未知目标文件；不得持有 SQL 写事务覆盖整个大文件复制过程；不得删除用户源文件。

### 5.6 取消、重试与部分成功

- 复制阶段取消必须让 worker 停止并关闭句柄、清理本次可确认的暂存文件；其他已经导入的文件不回滚。
- 到达短提交临界区时，不宣称可以撤销已提交文件；显示“正在完成入库”，完成后再处理退出。
- 一批文件部分失败时逐项保留结果，不用一个绿色 Toast 掩盖失败。
- 重试针对失败项。进程重启后不持有源文件授权，需重新选择，不后台扫描寻找原文件。
- 去重、重试和双击按钮不得产生重复导入；终态以数据库查询为准，不能只依赖易丢的前端事件。

## 6. 中断、文件缺失和数据库故障

### 6.1 启动核对必须有限、可解释

仅核对应用自己的数据库、导入记录、暂存区和管理副本。**不扫描用户文件夹，不把未识别文件自动入库。**

| 中断位置 / 异常 | D3 应有结果 |
|---|---|
| 复制尚未完成，留下 `.part` | 标记中断，清理可确认属于本次尝试的残留；重试需重新选择源文件 |
| 已完成暂存但未发布 | 核对记录与文件；可安全收尾才继续，否则标记中断/待检查，不报告导入成功 |
| 正式文件已发布，SQL 尚未提交 | 用已落盘的尝试记录、相对路径、大小和摘要核对；信息完整则幂等补齐同一素材记录，否则隔离并提示 |
| SQL 已提交，前端未收到确认 | 查询后返回既有成功结果，不重复复制、不再建一条素材 |
| 数据库有记录，管理副本不存在 | 保留标题、标签、收藏与归档记录，播放器显示“管理副本缺失”，不删除数据库记录 |
| 有正式目录文件但无可信归属记录 | 不自动删除、不自动入库；登记待检查，必要时隔离，说明处理方式 |
| 数据库损坏 / 无权写入 / schema 太新 | 显示具体阻断与只读诊断，不退回演示假装成功，不空库覆盖 |
| 重启后失去源文件选择授权 | 不恢复原始路径扫描或静默重读；要求重新选择文件 |

D3 不承诺强制断电、磁盘损坏等所有故障下零损失。必须报告已测试的崩溃窗口和剩余限制。

### 6.2 同一素材的缺失修复

正常重复导入只返回既有记录，但**既有管理副本缺失时不能永远返回“已存在”而无法使用**。

- 用户重新选择同一字节内容，摘要匹配既有素材后，允许通过同一受控导入流程补回缺失副本。
- 保留原 asset id、标题、标签、收藏、归档和路由；结果为“已修复管理副本”，不是第二条素材。
- 修复也使用暂存、短提交和导入记录；区分 import / repair 结果，不覆盖仍存在的未知文件。
- 不同内容不自动替换旧素材；作为新的候选素材处理。不能实现一个不受约束的“替换任意路径”接口。
- D3 不扩展为外部原文件重定位、长期引用模式或素材库迁移功能。

### 6.3 开发保护与产品备份不是同一阶段

D3 开发前保留 `shell.json`、D2 包和工作区保护副本，是实施安全措施；不代表 D7 产品级备份功能已经完成。

- 触碰已有 D3 数据库前，应关闭相关应用进程并确保数据库连接关闭后复制数据集合，或采用一致性快照方式。[T4][T5]
- 不把正在写入的 SQLite 主文件单独复制成“完整备份”。
- 故障测试只能针对独立测试数据；不得损坏用户正式资料以证明恢复能力。
- 回退源码不等于降级业务数据库。保留 D3 数据与版本信息，不能用 D2 回退操作把新增个人素材删除。

## 7. 原生媒体加载与权限

### 7.1 受控媒体地址

默认优先使用当前 Tauri 版本提供的本地 asset protocol，限定到应用管理的正式媒体目录，并按实际平台补充必要 `media-src`。`convertFileSrc` 只是路径到地址的转换，不替代文件权限和 CSP。[T1][T2]

实施要求：

1. 页面只提交真实 `assetId`，由 Rust 根据个人库解析管理副本。
2. Rust 再检查文件属于受控根目录、是常规文件、未逃逸、存在且可读。
3. 由原生 adapter 生成/接收可播放地址，页面只消费 `PlaybackSource`；地址不写入数据库，不作为永久路径。
4. 只为管理副本开放必要范围。**禁止 `$HOME/**/*`、整个 `$APPDATA/**/*`、根目录或任意 `file://` 放行。**
5. `shell.json`、SQLite、`.part`、日志和恢复区通过直接媒体 URL 请求也应被拒绝；不能只测试 IPC。
6. 不用本地 HTTP 服务绕过权限，不开启任意远程导航，不关 CSP，不打开通用 shell/fs/SQL 权限。
7. 若内置协议不能满足实测需求，先记录失败证据；只有必要时才实现按 asset id 限定的最小媒体协议，并覆盖 seek 所需的 Range 行为、取消读取和越界测试。不得提前造复杂服务器。

### 7.2 Capabilities 不代替 Rust 输入校验

Tauri 官方说明 capabilities 约束 WebView 暴露面，但不会自动修复不安全 Rust 命令；自定义应用命令的暴露方式也必须核实。[T3]

- 将新增调用限制到现有可信主窗口和必要命令，审查生效的 capability 集合，避免权限叠加放宽范围。
- 明确配置/验证新应用命令的调用边界，不假定“没有 fs 插件，所以自定义读文件命令天然安全”。
- 读取文件、处理 selection token、解析素材路径、生成媒体地址的 Rust 入口都进行参数与归属检查。
- 负向测试覆盖：伪造 asset id、伪造/过期 token、`..`、绝对路径、符号链接逃逸、超长字段、HTML 文本。
- 不暴露任意路径 `readFile`、`deleteFile`、`executeSql` 或 `openUrl` 作为方便开发的捷径。

### 7.3 播放行为与元数据

- 复用现有播放器与拆解页布局，保留播放/暂停、seek、倍速、时长显示、正常焦点与键盘操作。
- 新打开/恢复的个人视频默认暂停，用户点击后播放，不突然发声；切换素材停止旧视频和音频。
- 实际加载成功后记录已验证的时长/尺寸；未知显示“尚未读取”，不是零时长/虚构尺寸。
- 媒体加载结果传回 Rust 时按 asset id 归属、当前内容和字段范围校验；拒绝 NaN、Infinity、负数和过期视频的异步回写。
- “有画面”“有声音”“seek 可用”分别验证。无声短片不能作为音轨通过证据。
- 编码不可用、文件损坏、协议无权访问、文件缺失应有区分，不统一归咎于“网络错误”。
- 大文件以流式/协议方式提供，不能将整片经 IPC 转成 base64；需验证向中后段 seek，而不只验证播放第一帧。
- 返回素材库或切空间时清理事件/句柄/旧播放源，避免双重声音和重复保存元数据。
- D3 不要求记住播放进度；重启恢复正确素材即可。不得为实现“恢复”而新增字幕、笔记或脚本存储。

### 8.1 编辑和保存语义

- 素材详情优先沿用已有表单，并采用明确“保存”操作；Rust 确认事务后才显示“已保存到本机”。
- 保存中禁重复提交；失败保留用户当前输入，允许重试，不把内容清空或偷偷退出页面。
- 收藏/归档可用短操作；采用乐观 UI 时必须能回滚并说明失败。
- 未提交的个人素材资料编辑也要纳入现有离开/退出保护；这不是提前实现 D5 自动保存。
- 中文输入法组合时不截断文本、不因 Enter 候选确认而误提交；复用现有组件再补实机检查。
- 用数据源和空间标识避免页面缓存串库；不要让最后到达的演示请求覆盖个人数据。

### 8.2 路由与空间恢复

- 沿用现有 hash 路由，不改成浏览器服务端路由，不要求开发服务器在线。
- 个人深层路由中的 asset id 在数据库就绪后再解析；等待期间显示加载，不抢先判断“素材不存在”。
- 素材不存在时给出返回素材库；已归档时明确归档状态；副本缺失时保留资料并给修复路径。
- 演示仍从 fixtures 重建会话，不将其写入 SQLite；演示重置只影响演示 Repository。
- 切到演示、重置演示、退出演示再回个人，个人素材、收藏和标签必须不变。
- 沿用 `shell.json` 的当前格式和既有空间恢复规则；必要最小变更须有兼容测试，不无理由另建偏好系统。

### 8.3 窗口和退出生命周期

- 保留 D2 已修复的受控 Cmd+Q，覆盖菜单退出及实际应用退出请求，不能退回绕过保护的预定义 Quit。
- 无导入/待保存操作时，已成功保存的素材资料不出现虚假的“未保存”提醒。
- 导入进行中退出：提供“继续导入”和“取消未完成导入并退出”；后者要等待安全停止与清理/终态写入。
- 正在短事务提交时先完成一致性收尾，再结束进程；不承诺杀进程可撤销已提交素材。
- Cmd+W 继续沿用 D2 隐藏语义；重激活不得重复初始化数据库、重复迁移或重复导入。
- 重复启动/重开请求不得建立两个独立导入队列同时写同一资料库。先核实当前壳机制，必要时做最小单实例/写入所有权保护，并记录依据。

## 9. 接口与错误契约

以下是语义示例，不是已存在的项目 API。应映射到 D2 的类型和 adapter 命名，保持一个真源。

```ts
interface PersonalMediaPort {
  chooseLocalVideos(): Promise<SelectionResult>; // 原生选取，取消为正常结果
  startImport(selectionToken: string): Promise<ImportBatch>;
  getImportBatch(batchId: string): Promise<ImportBatch>;
  cancelImport(batchId: string, attemptId?: string): Promise<CancelResult>;
  listAssets(query: AssetQuery): Promise<AssetPage>;
  getAsset(assetId: string): Promise<VideoAsset>;
  updateAsset(input: AssetPatchWithExpectedRevision): Promise<VideoAsset>;
  setArchived(input: ArchiveChangeWithExpectedRevision): Promise<VideoAsset>;
  resolvePlayback(assetId: string): Promise<PlaybackSource>;
}
```

约束：

- `SelectionResult` 不给页面可任意替换的源路径；token 有范围和生命周期，启动后的尝试由原生持有。
- `PlaybackSource` 是当前会话内使用的媒体描述，不成为数据库里的永久 URL。
- `VideoAsset` 中无演示分析、虚假作者/平台热度、虚假 AI 结论；个人素材来源是手动导入。
- 字节进度事件可作为 UI 通知，但列表/终态查询是恢复真实状态的依据。
- 事件要有 batch/attempt id，页面订阅在卸载时清理；新页面可通过查询恢复当前批次。
- 不为未来插件开放 HTTP/自定义 URL scheme。只在接入文档中说明未来插件经独立授权 adapter 调用同一应用服务，而非直接写 SQLite。

建议错误类别，允许映射已有枚举：

| 类别 | UI 应对 |
|---|---|
| `DB_INIT_FAILED` / `SCHEMA_TOO_NEW` | 资料库不可用与诊断，不自动重建 |
| `VALIDATION_FAILED` / `LIMIT_EXCEEDED` | 指明字段/文件限制，保留可修正输入 |
| `SELECTION_EXPIRED` / `ACCESS_DENIED` | 重新选择或说明权限，不扩大访问范围 |
| `SOURCE_CHANGED` / `DISK_FULL` / `IO_FAILED` | 真实导入失败，源文件不变，可针对失败项重试 |
| `ASSET_NOT_FOUND` / `MANAGED_FILE_MISSING` | 保留正确页面状态，提供返回或同内容修复 |
| `PLAYBACK_UNSUPPORTED` / `PLAYBACK_FAILED` | 不宣称已可播，不虚构编解码原因 |
| `REVISION_CONFLICT` | 不覆盖新数据，刷新并让用户重新确认 |
| `NOT_CONNECTED` | 沿用 AI/下载/雷达未接入说明，无 fake job |

错误面向 UI 的字段至少有 code、message、可重试性和安全关联 id。完整源路径、视频内容、数据库内容不写入默认诊断；显示文件名也按纯文本处理。

## 14. 完成定义与必须停止的情况

### 14.1 允许称为“D3 核心完成”的条件

真实个人素材从原生选择器进入管理副本和 SQLite，修改资料/收藏/归档可保存，最终 `.app` 能播放已测正向素材并 seek，退出重开仍能找到同一素材；演示隔离、源文件保护、受限媒体访问与中断核对不失效；D2 核心交互不回归。

同时交付当前源码对应的桌面包、测试结果与限制。声音、特殊编码或某些环境未实测时，应在状态中明确保留，例如“D3 核心闭环完成；原生音频人工确认待验”，**不能称为全部验收通过**。

### 14.2 以下任一项属于核心阻断

- 个人素材仍只是内存/浏览器缓存，重启丢失。
- 只记录原文件路径，删除/移动原文件后没有管理副本可用。
- 视频只在开发浏览器可播放，最终 `.app` 无法验证正向素材。
- 打开任意 home/AppData 读权限、关 CSP 或用通用任意路径命令绕过加载问题。
- 复制中断产生伪成功，重复导入覆盖源文件/已有个人资料。
- 演示重置影响个人数据库，或者个人页面混入示例分析。
- 改坏品牌 identifier、既有 Cmd+Q、独立启动、窗口或深层页行为。
- 只提交计划/截图，未有实际 D3 原生代码和产物，却称开发完成。

遇到阻断先修复。若环境确实无法完成，应交付可检查的部分成果、失败证据和下一条具体任务，保持“未完成”状态，不返回空泛的“等以后再做”。

D3 结束后只列下一阶段前提：**D4 可在已稳定的个人媒体和 asset id 上增加字幕与个人时间笔记。** 本轮不创建这些功能，不提前授权，也不因为数据库现已存在就把所有演示表单转为个人持久化。
