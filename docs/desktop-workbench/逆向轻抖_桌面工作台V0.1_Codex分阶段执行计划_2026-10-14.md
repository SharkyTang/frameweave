# 1. 已确定需求、工程建议与未核实事实

## 1.1 用户已经明确的需求

1. 产品是**桌面工作台**。
2. 目标是帮助用户成为更优秀的视频创作者，而非单纯下载或转写视频。
3. 长期流程：筛选参考视频 → AI 分析并提炼制作方法 → 指导原创创作 → 作品复盘。
4. 当前先开发工作台界面与框架；视频、视频文案下载插件先独立开发，以后再接。
5. 未来希望加入主动发现热门视频的“爆款雷达”，但不是当前必须实现的能力。
6. 本次交付给 Codex 的是详细执行计划与提示词；不把规划写成已完成代码。

## 1.2 本文提出的默认工程方案

- macOS / Apple Silicon 优先，Windows 与 Linux 只保留结构上的可扩展性，本轮不承诺已适配。
- 没有成熟桌面工程时，默认 **Tauri 2 + React + TypeScript + Vite + Rust + SQLite**。
- 首版采用浅色、克制紫蓝强调色、中文、接近 Mac 桌面工具的设计方向。
- 本地媒体默认“复制到工作台资料库”，以便重启后稳定播放；外部引用模式后补。
- 首版真正实现手动管理与编辑；AI 只预留入口、数据结构和明确标识的示例。

这些是本执行计划的建议，不冒充用户已指定的框架或最终品牌。若现有仓库已有可维护的 Electron/Tauri 桌面应用，优先沿用，记录差异，不为了统一技术名词进行迁移。

## 1.3 历史线索，只用于避免破坏既有项目

此前交流描述过 Chrome 扩展、本机 Python 服务、视频下载、语音识别、字幕时间对齐与校对。曾提到 `127.0.0.1:8766`。这些内容**本次未通过仓库验证**。

本轮仅定位其工程边界和已有文档，不要求启动全部服务、不要求跑模型评测、不要求等插件完成。不要把历史端口当成已经确定的工作台 API，不要自动连接、探测或占用它。

产品暂用“逆向轻抖 / AI 视频创作工作台”作为工作名称。不得擅自把曾经建议过的仓库名当作已确认品牌，也不因此重命名用户仓库。

## 3.3 最终验收故事

在插件、Python、AI 服务都没有运行的情况下：

> 我从 Finder 启动工作台，导入一个自己的本地视频；可以播放、加标签、写一条带时间点的学习笔记；从这条素材创建原创创作项目，填写简报、脚本、分镜和拍摄清单；把一个方法保存到方法库；导出 Markdown 创作包；退出应用并重新打开，内容仍在。AI 和下载入口准确显示“尚未接入”，没有伪造结果。

**满足这个故事，才是可用的桌面框架；只有截图、网页链接或临时内存数据，不算完成。**

# 4. 桌面架构与选型

## 4.1 默认架构

```text
macOS 桌面应用 .app
│
├── React + TypeScript UI（打包到应用内）
│   ├── 页面、导航、播放器、编辑器
│   ├── 领域类型、状态校验、用例服务
│   └── 端口接口：素材 / 项目 / 媒体 / AI / 插件 / 雷达
│
├── Tauri / Rust 本地层
│   ├── 受限 commands / events
│   ├── SQLite Repository 与迁移
│   ├── 原生文件选择、复制、导出、备份
│   └── 本地媒体访问、窗口与生命周期
│
└── 本机资料
    ├── SQLite：素材元数据、项目、笔记、设置
    ├── library：应用管理的视频文件
    └── cache：可重建的封面和临时文件

未来（本轮不接入）：
插件 / Python 服务 → 独立适配器 → 已有领域接口
AI 模型服务       → AnalysisPort / CreationPort
榜单数据源        → TrendPort
```

Tauri 可通过 commands 在前端与 Rust 之间传递参数、结果和错误；macOS 界面运行在系统 WebView 中。[T1][T2]

这里的“桌面应用”指真实应用包与本地系统能力，**不等于全部界面使用 SwiftUI/AppKit 控件**。采用 Web UI 技术是实现选择；最终使用方式仍是启动 `.app`，不是要求用户打开浏览器。

## 4.2 前端和本地层职责

- React 组件只调用用例服务/Repository 接口，不直接散落 SQL、绝对路径、HTTP 请求或 Tauri `invoke`。
- `adapters/desktop` 统一封装 Tauri 调用；`adapters/demo` 提供明确的示例数据；`adapters/disconnected` 处理未接入能力。
- 默认由 Rust Repository 独占工作台 SQLite 的业务写入。建议使用 `rusqlite`，锁定经本机验证的版本。
- 文件复制、校验和计算、备份等放到受控后台任务，不堵塞 UI；使用有限并发，不搭建通用任务平台。
- 若现有工程已有官方 SQL 插件或另一套可靠本地存储，允许继续使用，但通过 Repository 收口；**不得在同一轮新建两套数据库访问方式**。
- D0 只需一份简短 ADR 说明实际选择、复用部分和取舍，不花数轮比较框架。

## 4.3 运行边界

开发命令可以同时启动 Vite 和 Tauri；但交付的应用必须加载随包内置的静态资源。

生产运行不得依赖：

```text
localhost 上的 Vite / Next.js 开发服务器
Chrome 扩展是否安装
Python 服务是否启动
用户另开终端运行命令
登录第三方网站
外部网络图片、字体、JavaScript CDN
```

桌面项目不要引入需要常驻 Node 服务的页面服务端。浏览器预览仅用于组件调试，不作为桌面完成的证据。

Tauri 官方提供 `.app` 与 DMG 等桌面打包能力；构建、签名、公证是不同交付项。[T3][T4]

## 4.4 依赖与现有工程保护

- 沿用已有包管理器、锁文件和组件库；没有时再选择一套。
- 本地层依赖和桌面依赖不进入插件的 Python 环境。
- 不通过升级整个仓库、改所有锁文件、移动插件目录来换取新工作台可运行。
- 已有 Electron 桌面工程可以沿用；此时用 preload/IPC 与受限主进程接口承担同样边界，不能绕过安全隔离。
- 所有框架 API、权限与构建命令以安装版本和官方文档核实，不拼接旧版示例。

## 6.4 桌面行为

- 保留正常的 Mac 关闭/最小化/全屏窗口控件；标题栏不压住按钮和输入框。
- 菜单至少包含应用、文件、编辑、窗口；复制、粘贴、撤销、选择全部按系统习惯工作。
- `Cmd+N` 新建创作项目；`Cmd+O` 导入素材；`Cmd+S` 保存当前编辑；`Cmd+,` 设置。
- `Cmd+K` 打开本地搜索/命令面板；`Esc` 关闭弹窗并还原焦点。
- `Cmd+W` 关闭窗口与 `Cmd+Q` 退出应用要区分；关闭最后窗口后的行为按当前框架实现并记录，保证 Dock 可重新打开工作台。
- 普通关闭/退出前处理未落盘编辑；保存失败必须可见，不能安静地丢弃。
- 播放空格快捷键只在播放器上下文生效，不能劫持正文输入。
- 窗口尺寸和最后页面可恢复；拔掉外接屏后窗口不能恢复到屏幕外。
- 首版单主窗口；重复打开应用时聚焦现有实例，避免两个窗口相互覆盖草稿。
- 不默认开机启动、不默认驻留托盘、不自动申请无关系统权限。

# 7. 页面级实施规格

## 7.1 工作台首页

**目的：让我立即知道接下来学哪条视频、继续做哪个作品。**

布局优先级：

1. 顶部“导入参考素材”“新建创作项目”；链接入口文案为“保存参考链接”，不是“下载”。
2. 中央“继续创作”：最近项目、上次编辑时间、下一项未完成拍摄任务。
3. “最近学习的素材”：缩略图、标签、笔记数，点击进入学习空间。
4. 小块“我的待办”：从真实项目清单计算，不生成无依据的 AI 训练建议。
5. 本地概览最多 3 个辅助数字：真实素材数、创作中项目数、已保存方法数。

无数据时优先引导导入本地视频或查看示例，不显示虚构的 28 条视频、12 次分析等数字。

## 7.2 灵感素材库

- 原生文件选择；拖放文件可以后于选择器完成，但 D3 结束前应支持。
- 新增手动参考链接、标题、备注、作者字段（可空），**不请求远程内容**。
- 搜索标题/备注/标签；按收藏、来源类型、是否有本地文件筛选；排序按最近导入/更新。
- 列表与网格共用同一数据源，状态和选择不重复维护。
- 素材详情显示文件状态、文案/字幕状态、笔记和关联项目。
- 可编辑标题、标签和学习目标；从素材“开始创作”只创建项目并带入参考关系。
- 支持归档/恢复；删除元数据不删除用户外部原文件。
- 只有链接的记录显示“未关联本地视频”，不伪装可播放；可稍后手动关联文件。

## 7.3 视频拆解 / 学习空间

宽屏建议“播放器与时间轴 + 拆解/笔记 + 可折叠参考面板”，较窄时改为上下布局。

**真实功能：**

- 播放/暂停、进度拖动、音量、倍速、全屏，记录该素材上次播放位置。
- 手动导入已有 `.srt` / `.txt` 文案；这不是调用下载插件或进行语音识别。
- SRT 显示时间段和句子，点击跳到视频位置；TXT 只有文本，不生成假时间戳。
- 在当前播放时间建立笔记，例如“00:07 先展示问题，再解释原因”。
- 手动选择拆解维度：开头、结构、画面/镜头、节奏、声音、可复用方法。
- 笔记可以修改、删除、引用到方法库或创作项目。
- 显示来源：手动笔记 / 导入字幕 / 演示分析 / 未来 AI 结果。

**未接入功能的正确表达：**

- “AI 深度拆解”显示未接入说明，不开始虚假排队。
- 可以“查看示例拆解”，必须切换到明确的示例素材，不把示例套到用户视频上。
- 没有镜头检测时不画真实镜头边界；可以显示进度条和手动时间标记。
- 没有声音分析时不声称识别了 BGM、节拍或音效；不以装饰波形冒充分析。
- 未来报告必须能表达“观察”“推测”“建议”和“没有足够证据”。

## 7.4 创作导师工作区

本轮名称可以保留“创作导师”，但主要操作是**可用的创作编辑器**，AI 入口标记未接入。

创作简报字段：主题、受众、目标时长、发布平台（可选）、表达风格、出镜意愿、设备、地点、独立/多人制作、参考素材、希望借鉴的方法。

编辑页包含：

- 选题与核心表达：人工输入，不编造“AI 推荐指数”。
- 脚本：分段编辑、段落名称、估计时长（手填）、旁白/对白、备注。
- 分镜表：镜号、计划时长、景别/角度、画面内容、台词、道具、拍摄提示。
- 拍摄清单：地点、道具、镜头、人员事项与勾选状态。
- 剪辑说明：镜头顺序、字幕要点、转场想法、声音备注。
- 导出：Markdown / TXT，分镜表 CSV；不生成或导出成片。

主按钮必须真实：`保存草稿`、`使用空白模板`、`导出创作包`。`AI 生成方案` 为未接入态。

固定模板要标“模板”，不能标“AI 已根据你的作品学习生成”。自动保存状态显示“保存中 / 已保存 / 保存失败”；用户修改不会被重新加载的示例覆盖。

## 7.5 创作方法库

每张方法卡包含：标题、适用场景、具体做法、注意事项、标签、来源素材/时间点、用户是否验证过。

可从笔记转换，也可手动新建。支持搜索、编辑、归档、在项目中引用。

“保存方法”是存储知识，不称为模型训练、微调或 AI 已掌握用户风格。来源素材被归档时保留来源标题快照与关系，不把卡片变成无法理解的孤立文本。

## 7.6 我的作品与复盘

项目阶段：构思 → 脚本 → 待拍摄 → 剪辑中 → 待复盘 → 已归档。阶段由用户选择，不凭素材导入自动宣告“作品完成”。

作品页关联现有创作项目，避免再建一套重复“作品项目”。允许导入用户自己的成片，并保留多个作品版本的标题与日期。

手动复盘字段：这次目标、做得好的地方、问题时间点、下一版修改、下次练习。可以对照打开参考素材，但本轮不做自动打分与 AI 评判。

## 7.7 爆款雷达

- 显示“规划中：未来从可用数据源寻找值得学习的视频”。
- 允许保存感兴趣领域与排除主题，这只是偏好设置。
- 不显示真实感很强的“今日榜单”“已追踪 1024 条”“增长 380%”。
- 示例卡仅在演示空间出现，显著标记“虚构示例 / 非实时数据”。
- 不做定时器、爬虫、浏览器自动化、账号授权或自动抓取。

## 7.8 设置

- 应用信息：实际版本、运行模式、本地数据目录、可复制的脱敏诊断信息。
- 外观：仅提供已实现的主题与字号/密度选项。
- 数据：元数据备份/恢复、清理可重建缓存；清理前说明范围。
- 演示：进入/离开示例空间、恢复示例，绝不清空个人空间。
- 插件连接：默认“本版本尚未接入”，不是绿色在线。
- AI：默认“未配置”；本轮不要求输入 API Key、不收集任何密钥。
- 不因为用户尚未配置 AI 而阻止打开其他页面。

# 8. 数据模型、持久化与本地媒体

## 8.1 最小领域对象

按阶段增加表，不在 D1 就实现所有未来 AI 表。领域类型从 D2 开始，真实持久化在 D3 接入。

| 对象 | 最小字段/关系 | 首次需要 |
|---|---|---|
| VideoAsset | id、用途（参考/自己作品）、标题、备注、来源链接、作者可空、标签、收藏、文件状态、时间 | D2/D3 |
| MediaFile | id、assetId、应用内相对路径、原文件名、字节数、内容校验和、时长可空、播放兼容状态 | D3 |
| Transcript | id、assetId、格式、来源、原始文本、当前修订版本、时间单位 | D4 |
| TranscriptSegment | id、transcriptId、startMs、endMs、text、顺序 | D4 |
| LearningNote | id、assetId、可选时间段、维度、正文、来源类型、revision | D4 |
| CreativeProject | id、标题、阶段、简报、参考素材关系、脚本/分镜/清单、revision | D5 |
| MethodCard | id、标题、场景、步骤、限制、标签、来源关系/快照、用户验证状态 | D5 |
| WorkVersion | id、projectId、assetId、版本标题、日期、手动复盘 | D5 |
| LocalJob | id、类型、状态、真实进度可空、错误、createdAt/updatedAt | D3 |
| AppSettings | schemaVersion、外观、窗口、雷达兴趣、非敏感偏好 | D3/D6 |
| AnalysisReport | schemaVersion、assetId、覆盖范围、来源、findings、证据引用 | D6 仅契约 |
| IntegrationStatus | 配置状态、能力可用性、版本兼容状态、最后错误 | D6 |

所有主键使用稳定 ID。所有对象需明确个人空间或演示空间；严禁把示例写入个人数据库后靠标签过滤补救。

时间规则：视频片段时间统一使用整数毫秒；存储时间使用带时区的 UTC 时间戳，展示时转用户本地时间。外部插件以后若返回秒，由适配器转换，不能混用。

## 8.2 状态不要互相冒充

分别记录：

```text
媒体可用性：link_only / available / missing / unsupported / import_failed
字幕状态：none / imported / edited
AI 能力：not_configured / disconnected / ready / incompatible / error
本地任务：queued / running / succeeded / failed / cancelled / interrupted
草稿保存：clean / dirty / saving / saved / error / conflict
来源类型：user_authored / user_imported / demo / external_provider（未来）
```

视频“已导入”不等于“已转写”；“可以播放”不等于“AI 已看过”；“生成了模板”不等于“AI 已生成方案”。

进度无可测分母时显示阶段名称和不确定进度，不使用随机数或固定计时器伪造 0–100%。

## 8.3 数据库与文件布局

```text
<平台 API 返回的 AppData 路径>/
├── db/workbench.sqlite
├── library/<mediaId>/<安全生成的文件名>
├── staging/<importJobId>/
└── settings/（仅在确有需要时）

<平台 API 返回的 AppCache 路径>/
└── thumbnails/...
```

目录通过运行时平台 API 获取，禁止写死用户名字、桌面路径或 `~/Downloads`。稳定应用标识从 D0/D1 就确定并记录；不能每次改标题都换数据目录。

本轮默认数据库由桌面应用所有；插件/Python 不直接写工作台 SQLite。以后经导入契约或 API 适配器交换数据，避免跨进程共享内部表结构。

迁移要求：有版本、事务、测试数据、升级路径；对同一版本重复启动不得重复插入种子或执行破坏性建表。不要启动时删库重建。

如采用官方 SQL 插件，它已有迁移支持，但具体路径与权限须以安装版本核实，不能把示例中的目录假定为本项目目录。[T5]

## 8.4 媒体导入：默认复制，不依赖临时浏览器对象

推荐流程：

```text
用户选择文件/拖放文件
→ 原生层确认用户授权与文件性质
→ 建立本地任务
→ 流式复制到 staging，并计算校验和
→ 验证复制结果
→ 移到受管理的 library 路径
→ 数据库事务登记 MediaFile 与 VideoAsset
→ 通知 UI，尝试播放并读取可获得的元数据
```

要求：

- 复制前显示文件大小和“将占用额外磁盘空间”；空间不足时给出可恢复错误。
- 不把完整视频读入前端内存再 Base64 存储；大文件使用流式 I/O。
- 相同内容默认提示“已在资料库”，允许用户复用；同名不同内容不得覆盖。
- 文件系统与数据库并非同一事务：实现 staging 清理和启动时的中断恢复，避免孤儿记录或半成品被标成功。
- 原始外部文件只读，任何归档/删除操作都不删除它。
- 若以后支持外部引用模式，单独定义授权持久化与丢失重定位；本轮不为省复制功能而悄悄依赖脆弱路径。
- 重启后播放依靠资料库路径重新解析，不持久化 `blob:` URL。

## 8.5 播放与文件访问

通过 `MediaPort` 获取可播放来源；内部文件路径、临时 URL 与过期策略不暴露到组件业务逻辑。

使用 Tauri asset protocol 时要明确允许的媒体目录及 CSP；官方文档指出播放资源受作用域控制，静态授权与运行时选择文件的授权不是同一回事。[T6]

**本计划的限制：**只允许加载应用管理的媒体/缩略图目录；不要为了修复播放就开放整个用户主目录，更不能开放包含数据库、日志、凭证的所有 AppData 文件。

最小验收媒体采用 H.264/AAC MP4 样本。其他容器/编码以目标 Mac 的实际播放测试为准；不能因为选了 `.mov` / `.mkv` 文件就声称支持其全部编码。无法播放时保留资料记录并提示兼容性限制，本轮不因此增加转码管线或 FFmpeg 安装前置。

文件名包含中文、空格、`#`、`%` 时，选择、复制、播放和重启均应工作；URL 编码和路径分隔交由平台适配器正确处理。

## 8.6 自动保存与恢复

- 编辑后建议约 750 ms 防抖保存，`Cmd+S` 立即提交；该时间是初始工程参数，不是严格实时保证。
- 每份草稿有 revision；保存携带预期版本，避免慢请求覆盖新内容。
- 只有数据库提交成功才显示“已保存”；失败时保留编辑缓冲并允许重试/导出。
- 切换项目或正常退出时等待待保存内容，失败则明确询问是否保留窗口。
- 异常崩溃恢复至少保证最后一次成功提交的版本；不能宣称任何未保存键入都不会丢失。
- 不把 `localStorage` 当素材、项目、字幕和脚本的主存储。临时 UI 状态可使用，但必须与真实持久层区分。

## 8.7 演示空间隔离

首次打开默认进入个人空工作区，并提供“查看示例”。演示空间使用独立 SQLite 文件或独立测试/演示 Repository，不能与个人空间共享可变记录。

示例需包括：可播放的自制短片/合法小样本、合理时间标记、一份示例拆解、一份示例项目、一张方法卡。记录素材来源与许可；不在线下载不明来源的爆款视频。

如果没有合适示例视频，显示清楚的未提供视频状态，不能拿一张静态封面冒充可播放短片。合成测试短片中的几何图形、文字等内容要与示例观察一致，不写不匹配的旅行镜头分析。

D2 的临时演示编辑应提示“仅演示，不保存到个人资料”；D3 以后演示空间也可独立持久化。重置演示只影响演示空间。

# 9. 未来接入契约：现在预留边界，不虚构已存在 API

## 9.1 对外只暴露小而明确的端口

以下是领域契约示意，D6 根据实际代码整理为可校验类型；不是现有插件的真实接口声明。

```ts
export type Milliseconds = number; // 运行时验证：整数、>= 0
export type DataOrigin =
  | "user_authored"
  | "user_imported"
  | "demo"
  | "external_provider";

export interface AppError {
  code: string;
  message: string;
  retryable: boolean;
  requestId?: string;
}

export type Result<T> =
  | { ok: true; value: T }
  | { ok: false; error: AppError };

export interface CapabilityStatus {
  state:
    | "not_configured"
    | "disconnected"
    | "ready"
    | "incompatible"
    | "error";
  available: boolean;
  reason?: string;
  apiVersion?: string;
}

export interface EvidenceRef {
  id: string;
  assetId: string;
  startMs: Milliseconds;
  endMs: Milliseconds;
  kind: "frame" | "transcript" | "audio" | "manual_note";
  sourceId: string;
}

export interface Finding {
  id: string;
  kind: "observation" | "inference" | "suggestion";
  text: string;
  evidenceIds: string[];
  origin: DataOrigin;
}

export interface AnalysisReport {
  schemaVersion: 1;
  id: string;
  assetId: string;
  origin: DataOrigin;
  provider?: string;
  model?: string;
  createdAt: string;
  coverage: {
    visual: "none" | "sampled_frames" | "video";
    transcript: "none" | "provided";
    audio: "none" | "provided";
    limitations: string[];
  };
  evidence: EvidenceRef[];
  findings: Finding[];
}

export interface AnalysisPort {
  getCapability(): Promise<CapabilityStatus>;
  request(input: {
    assetId: string;
    learningGoal?: string;
  }): Promise<Result<{ jobId: string }>>;
}

export interface AcquisitionPort {
  getCapability(): Promise<CapabilityStatus>;
  requestImport(input: {
    sourceUrl: string;
  }): Promise<Result<{ externalRequestId: string }>>;
}
```

同样为 `AssetRepository`、`ProjectRepository`、`MethodRepository`、`MediaPort`、`ExportPort`、`CreationPort`、`TrendPort` 定义实际用到的方法。不要提前设计一个无所不包的通用插件框架。

实现要求：UI 只依赖端口；未接入适配器返回 `NOT_CONNECTED` / `NOT_IMPLEMENTED` 等明确错误；不为点击反馈伪造 jobId 和成功状态。UI 禁用只是提示，服务层也必须拒绝未实现请求。

## 9.2 演示适配器不属于真实 AI

- `DemoAnalysisAdapter` 仅在示例空间读取固定示例报告。
- 个人素材调用默认 `DisconnectedAnalysisAdapter`，不能悄悄回退到示例。
- 用户修改过的报告和笔记有独立来源与版本，导入新结果不会覆盖。
- 未来真实服务是否支持画面、音频、字幕要由能力声明和实际输入记录表达，不能在 UI 中固定写“已完整观看”。

## 9.3 交换包示例：适配器测试，不要求插件立即实现

D6 可实现纯函数校验/转换并用于测试；默认不提供自动监听目录、不启动 HTTP 服务器。

```json
{
  "schemaVersion": 1,
  "packageId": "example-package-001",
  "source": {
    "provider": "user-selected-import",
    "externalId": "example-video-001"
  },
  "asset": {
    "title": "自制测试参考片",
    "purpose": "reference",
    "durationMs": 10000
  },
  "media": {
    "relativePath": "media/reference.mp4",
    "sha256": "<由导出方实际计算，不使用示例值导入>"
  },
  "transcript": {
    "origin": "user_imported",
    "segments": [
      { "startMs": 0, "endMs": 2000, "text": "示例开头" }
    ]
  }
}
```

上面的 JSON 是格式说明，不是可用于真实导入的完整包；测试夹具应生成正确校验和。

校验规则：版本明确；字段大小有上限；时间段有效；媒体路径只允许包内安全相对路径；拒绝 `..`、绝对路径、符号链接逃逸与无关文件访问。未经用户选择的包，不能授权读取其中声称的本地路径。

未来接入必须保证幂等：同一 provider + externalId 或 packageId 重复输入不无限新增；冲突时保留人工编辑，不用上游标题/字幕强制覆盖。

## 9.4 后续真正接入时的边界（不在 D0–D7 实施）

1. 先审计用户完成后的插件接口，再选择交换文件、受限本机 API 或 Native Messaging；本轮不锁死传输方式。
2. 未来连接状态应经过真实握手、版本与能力检查；旧端口仅是线索。
3. 如果采用本机 HTTP：仅绑定 loopback；鉴权、来源校验、范围限制、超时与取消均需设计。不能认为 `127.0.0.1` 自动等于安全，也不能只依赖 CORS。
4. 工作台拥有自己的数据目录和数据库；已有 Python 服务继续管理自身模型/任务，避免重复实现。
5. 以后接入只应主要新增/替换适配器并做契约映射，不修改每个页面；“完全无需任何改动”不是承诺。
6. 长任务事件要定义版本、幂等、重复/乱序和取消策略；这些不构成本轮实时任务服务的开发要求。

# 10. 安全、隐私与边界

## 10.1 本地应用不是无限文件权限的理由

Tauri 的 capabilities 用于限制前端可调用能力；自定义 Rust commands 自身仍需要校验参数和作用域，不能把安全全部交给配置。[T7]

本计划要求：

- 不暴露任意 SQL、任意文件读取、任意 shell 命令、任意 URL 下载给 UI。
- 读取媒体优先传 `mediaId`，由原生层从可信数据库解析路径，不接受组件随意指定绝对路径。
- 导入只处理用户明确选择/拖放的文件；不递归扫描个人目录或插件资料库。
- 导出使用原生保存对话框；覆盖已有文件前确认；取消选择不算操作成功。
- 记录路径时区分内部相对路径与用户展示名；日志不写完整字幕、私人脚本和用户目录全路径。
- 不在应用中加载带本机权限的远程网页；外部 http(s) 链接经校验后用默认浏览器打开。
- Markdown、字幕、导入报告都按不可信文本处理；不执行其中的 HTML、脚本或指令，不任意加载外部图片。
- CSP 生产配置不得为调试方便长期放宽；生产包不依赖远程脚本。
- 不默认收集遥测、上传崩溃报告或媒体；本轮根本不需要 API Key。

## 10.2 删除、备份与恢复

- 日常删除优先应用内归档/回收站；用户外部原文件永不随记录删除。
- 管理副本的彻底清理需展示影响范围与关联项目；不能自动清理仍被引用的媒体。
- V0.1 必做**元数据备份与恢复**：SQLite 快照、版本信息、媒体清单。界面明确“本备份不包含视频文件”。
- 如恢复目标不存在对应媒体，显示“文件缺失 / 请重新关联”，不要报告所有素材已恢复可播放。
- 数据库快照使用一致性备份方法，不能直接复制正在写入的数据库文件就宣称备份可靠。SQLite 与 rusqlite 提供相应备份 API。[T8]
- 恢复前暂停写入、校验版本与完整性、保留当前库备份；失败保留原库，不在一半失败时清空用户空间。
- 全量媒体打包、跨设备迁移和云同步后续再做，不阻塞当前首版。

# 12. 测试策略与验收矩阵

## 12.1 分清四种证据

1. **静态检查：**类型、lint、格式、构建。
2. **自动化逻辑测试：**领域规则、Repository、迁移、路径校验、解析器、端口契约。
3. **界面测试：**组件与浏览器层流程；可用 Vitest/Testing Library/Playwright 或已有工具。

Tauri 官方区分 mock runtime 和真实端到端测试；mock 不执行原生 WebView。当前可用的桌面自动化工具以实际环境和官方说明核实，不把浏览器 Playwright 结果直接当作 WKWebView/原生系统行为已通过。[T9]

能够自动测的先自动测；原生部分没有可用自动化时，提供短而明确的人工步骤和实际执行记录。未在 Mac 执行就写“待 Mac 验证”，不能用“应该没问题”替代。

# 14. 最终桌面交付标准

## 14.1 必须提供

- 可维护源码、锁文件、实际使用的框架版本与构建环境。
- 真实 `.app` 的名称、实际路径、构建命令和 Finder 启动方法。
- 本轮完成的 8 页界面、真实本地功能、演示/未接入能力清单。
- 数据库迁移、AppData 路径、元数据备份/恢复说明。
- 测试结果、未运行项、已知兼容性限制与真实桌面截图。
- 未来插件、AI、雷达适配器的文件位置与契约。

开发命令以下面形式为目标，**具体脚本名以实际 package.json 为准，交付文档不得抄不存在的命令**：

```text
安装依赖：使用仓库已有包管理器和锁文件
桌面开发：<包管理器> run desktop:dev
类型/测试：<实际已有的 typecheck / test / lint 脚本>
桌面构建：<包管理器> run desktop:build
原生测试：<实际适用的 cargo test / 已有测试命令>
运行产物：Finder 打开构建出的 .app
```

如果根仓库已有同名脚本，避免覆盖；给出从 desktop package 运行的精确命令。

## 14.2 不得混淆的状态

```text
React 页面写完 ≠ 桌面应用交付
开发窗口能开 ≠ 打包后的应用能独立运行
浏览器测试通过 ≠ Mac 原生窗口行为通过
有素材封面 ≠ 本地视频能播放
UI 显示已保存 ≠ 数据库提交已成功
导出元数据 ≠ 视频文件已经备份
读取示例报告 ≠ AI 已分析用户视频
本地构建成功 ≠ 已签名公证并适合公开分发
```

首次本机自用构建与对外分发是不同范围。签名、公证或 Gatekeeper 提示要真实说明，后续按官方流程处理；不通过关闭全局系统安全设置来掩盖打包问题。[T4]

# 15. V0.1 之后的路线（本轮不执行）

按用户完成插件的实际情况再安排，不提前绑定先后顺序：

1. **插件接入：**审计完成后的接口，建立真实握手、导入与字幕映射；复用工作台现有 Repository 和学习空间。
2. **真实 AI 拆解：**选择并验证模型输入/输出，接 `AnalysisPort`，补齐画面与声音证据，不将字幕摘要当成完整视频分析。
3. **AI 创作导师：**接 `CreationPort`，输出适合用户条件的原创方案，保留手动编辑和版本保护。
4. **爆款雷达：**核实可用数据源、授权与指标，再接 `TrendPort`；不保证能获取任意平台榜单或播放数据。
5. **进阶桌面能力：**外部媒体引用、全量媒体备份、多设备同步、其他系统安装包等，按实际需求单独授权。

当前框架应让这些能力能够接入，但不要求为了“未来扩展”先做完全部基础设施。
